## set
- Реализован как **сбалансированное дерево** (обычно красно-черное).
- Итераторы не инвалидируются при вставке/удалении других элементов (кроме удаленного).
- Под капотом — те же узлы, что и в map, но `value_type` = `Key`.
- Операции: `O(log n)`.

## multimap / multiset
- `equal_range(key)` — возвращает пару итераторов `[lower_bound, upper_bound)`, задающих диапазон элементов с ключом `key`.
- Вставка гарантирует, что **новый элемент с равным ключом** будет после старых (`insert` сохраняет порядок вставки для равных ключей).
- Удаление всех элементов с ключом: `erase(key)` — возвращает количество удаленных.
- Можно использовать как аналог "индекса" в БД.

## std::unordered_map internals 

**Хэш-функция:**
- `std::hash` специализирован для всех встроенных типов, указателей, `std::string`, `std::bitset`.
- Для пользовательских типов можно перегрузить через `template<> struct std::hash<MyType>` или передать функтор в шаблон контейнера.
- Хэш-функция должна быть **детерминированной** и давать минимум коллизий.

**Bucket (корзина):**
- Индекс бакета = `hash % bucket_count()`.
- `bucket_count()` обычно простое число (уменьшает вероятность кластеризации при модуле).
- `bucket_size(i)` — количество элементов в i-й корзине.
- Итератор обходит все корзины, пропуская пустые.

_Коллизия_ - 2 ключа получают одинаковый `hash code`.
Как разрешить коллизию:

1. **Коллизии и метод цепочек:**
- Каждый бакет — односвязный список (иногда вектор) узлов.
- `Node` хранит: `{pair<const Key, T> kv; size_t hash;}`.
- Хранение хэша ускоряет `rehash` (не надо пересчитывать) и сравнение (сначала сравниваем хэши).

2. **Метод открытой адресации**
Есть еще одна функция, которая каждой ячейке ставит соответствие другую ячейку. Идем по цепочке в "следующую", пока не станет свободно. Но тогда усложняется поиск. При удалении нужно не чистить ячейку, а ставить специальный флажок `erased`. В каком-то случае прийдется сделать `rehash`(за линию) в новую `hash table` размера `N`, где `N` - какое-то простое число. 

**Load Factor и Rehash:**
- `load_factor() = size() / bucket_count()`.
- `max_load_factor()` — порог (по умолчанию 1.0).
- При превышении `max_load_factor` делается `rehash(bucket_count * 2)` (или до ближайшего простого числа).
- `reserve(n)` — выделяет память под `n` элементов (вызывает `rehash(ceil(n / max_load_factor))`).

**Итераторы:**
- `forward_iterator`.
- Инвалидируются только при `rehash` (кроме итераторов на удаленный элемент).

**erase:**
- Для удаления из односвязного списка нужно знать предыдущий элемент.
- `erase(iterator)` работает за `O(1)` average, но может быть дорогим, если элемент не в начале бакета.
- `erase(key)` — вызывает `find(key)` и удаляет найденное.

**Почему нет `operator[]` для unordered_multimap:**
- Неоднозначность: по ключу может быть несколько значений.
